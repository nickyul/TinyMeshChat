# TinyMesh Chat

TinyMesh Chat — настольный P2P-чат на C++20, Qt 6 и libdatachannel для небольшой динамической комнаты. Центрального сервера и signaling-сервера нет: первое offer/answer-соединение с новым участником передаётся вручную строкой `tmc1:` или файлами `.tmcinvite` и `.tmcanswer`, остальные прямые каналы строятся автоматически.

## Что работает

- постоянная локальная identity с UUID;
- создание комнаты;
- приглашения от любого участника комнаты;
- импорт invitation и answer из текста или файла;
- non-trickle ICE и настраиваемые STUN-серверы;
- прямой надёжный WebRTC DataChannel;
- JSON-пакеты `peer.hello`, `chat.message`, `chat.ack`, `ping` и `pong`;
- эфемерные комнаты, roster, сообщения и состояния доставки только в памяти текущего запуска;
- ограниченная RAM-дедупликация сообщений без истории и повторной отправки после реконнекта;
- логические часы Лэмпорта;
- динамический список до 8 участников и автоматическое построение full mesh;
- маршрутизация служебных offer/answer через уже открытые P2P-каналы без передачи текста посредникам;
- отправка сообщения по всем открытым прямым соединениям;
- отображение участников, состояния mesh и количества ACK;
- редактирование STUN и сетевые диагностические сведения в GUI;
- сохранение signaling в файл и копирование в буфер обмена;
- консольная P2P-диагностика;
- автоматическое развёртывание Qt runtime после сборки.

## Требования

- Windows 10/11;
- Visual Studio 2022 с компонентами C++;
- CMake 3.25+;
- Qt 6.5+ с MSVC 2022 x64;
- vcpkg, встроенный в Visual Studio или указанный через `VCPKG_ROOT`.

На текущей машине проект автоматически находит:

```text
C:\Qt\6.8.3\msvc2022_64
C:\Program Files\Microsoft Visual Studio\2022\Community\VC\vcpkg
```

Для другой установки задайте:

```powershell
$env:VCPKG_ROOT = 'C:\dev\vcpkg'
$env:QT_ROOT = 'C:\Qt\6.8.3\msvc2022_64'
```

## Подключение нового пользователя

1. Любой участник комнаты нажимает `Пригласить`.
2. После завершения ICE он отправляет новичку строку `tmc1:` или `.tmcinvite`.
3. Новичок импортирует приглашение и возвращает созданный answer.
4. Пригласивший импортирует answer.
5. Список комнаты распространяется по открытым каналам, после чего недостающие прямые соединения создаются автоматически.

## Динамическая сетка

Участники обмениваются `peer.list`. Для каждой отсутствующей пары инициатор детерминированно выбирается по `peer_id`, поэтому встречные offer не конфликтуют. `mesh.offer` и `mesh.answer` передаются по существующим каналам с ограничением числа переходов и дедупликацией маршрута. При лимите 8 на каждом узле может быть до 7 прямых каналов.

Текст чата отправляется только по прямым DataChannel. Пригласивший участник не становится сервером сообщений.

## Данные и конфигурация

В каталоге `QStandardPaths::AppDataLocation` находятся:

```text
identity.json
config.json
```

`config.json` создаётся при первом запуске. STUN-серверы можно изменить через меню `Инструменты → Настройки STUN`; новые значения применяются к новым соединениям. Таймауты можно изменить в JSON после остановки приложения.

После перезапуска приложение не восстанавливает комнату, roster, сообщения или состояния доставки: нужно создать новую комнату либо импортировать свежее приглашение. Новый участник видит только сообщения, полученные после подключения. На диск записываются только стабильная identity и пользовательские настройки.

При обрыве не создавайте новую комнату. Любой доступный участник может создать новое приглашение; после восстановления первого канала остальные связи снова достроятся автоматически.

TURN и relay не используются. Поэтому соединение может не установиться при симметричном NAT, некоторых вариантах CG-NAT, блокировке UDP или корпоративном firewall.

## Сборка на macOS

Нужны Xcode Command Line Tools, CMake, Ninja, Qt 6.5+ для macOS и vcpkg. Укажите каталоги зависимостей:

```bash
export VCPKG_ROOT="$HOME/vcpkg"
export QT_ROOT="$HOME/Qt/6.8.3/macos"
bash scripts/build-macos.sh
```

Скрипт собирает приложение под нативную архитектуру текущего Mac, запускает `macdeployqt`, выполняет локальную ad-hoc подпись и создаёт `dist/TinyMeshChat-macOS.zip`. Для явного выбора архитектуры можно задать `TMC_OSX_ARCHITECTURES=arm64` или `x86_64`. Универсальную сборку можно запросить значением `arm64;x86_64`, только если Qt и все vcpkg-зависимости доступны для обеих архитектур.

На другом Mac распакуйте ZIP и запустите `TinyMeshChat.app`. Поскольку сборка не подписана сертификатом Apple Developer ID и не notarized, при первом запуске может потребоваться команда `Открыть` из контекстного меню Finder.

Каждый push в ветку `main` запускает workflow `Desktop builds`. Он собирает `TinyMeshChat-macOS.zip` и portable `TinyMeshChat.zip` для Windows 10/11 x64. Оба архива можно скачать на странице GitHub `Actions` из раздела `Artifacts` соответствующего запуска.
